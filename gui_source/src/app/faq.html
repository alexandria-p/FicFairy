About downloading from AO3

This page downloads fanworks using AO3's own download links. Click here to read AO3's page on how they handle this.

Which run to use

  • Quick Scan - your go-to for routine checks. It looks back only as far as your last scan, picking up any new bookmarks and fics updated since then. Far quicker than a Full Scan, and far lighter on AO3 as it does not need to request any fics it already has.
  • (Full scan) Reindex & Update All - reads your whole bookmarks list, so it takes much longer. Useful for repairing your library.
  • Custom run - a Full Scan, with some extra options.
  • Download/update a specific fic or several fics - download any fics from AO3 by their URL or ID. This always fetches a fresh copy.

Only one run can be performed at a time.

Why do I need to log in?

You don't need to 😊 Logging in is optional.

If you choose to download or update fics by URL or id, you can bypass logging in entirely.

To scan your bookmarks, FicFairy needs your username so it can find your bookmarks page. Your password is still optional here.

However, you will need to log in to access:

  • Your private bookmarks
  • Works restricted to registered users

Your password is sent straight to AO3 to log in and is never stored by this page.

Run history

Check the History tab to see the last 100 runs - including their status, and any issues they encountered. Some unsuccessful runs can be retried, and attempt to pick up where the last one left off.

What does not survive a download

  • No work skins
  • Custom styling (text styled as chat logs, handwriting etc)
  • Embedded audio and video

This app only downloads what AO3 provides. This means that any custom styling an author applied to their work is not carried into a downloaded copy - so text laid out as chat logs, handwriting, redactions or newspaper clippings will read as ordinary paragraphs. Sorry!

Images are normally embedded inside the downloaded work as a link, and will still display when you read it (so long as the original image is still accessible).

Custom run can also save embedded images as separate files, in an images subfolder. That is for when you want the pictures themselves - it does not repair a work whose images are already inaccessible, and it makes the run considerably longer, because every fic needs its own page fetched on top of its files. Very large images sometimes fail.

How indexing works

Downloading a fic results in the work being saved to your library in whichever format(s) you requested. Indexing it is something FicFairy does to record each work's metadata, so it can show you your library almost instantly in the Works and Collections tabs. An index is a small .json file describing a work - title, author, tags, summary, word and chapter counts, when AO3 last updated it.

One AO3 account per library

FicFairy is built to keep track of the bookmarks of a single AO3 account. Scanning a second account's bookmarks into the same library mixes the two together - it can be done, but expect certain features like Quick Scan to misbehave. If you decide to switch users, try running a Full Scan instead before doing anything else.

When something cannot be downloaded

FicFairy attempts to retrieve works from FicHub, when they cannot be reached on AO3. As FicHub serves cached versions of works, they may be out-of-date - the run will warn you if it detects this.

Deleted and hidden bookmarks

Any bookmarks that were un-bookmarked on AO3 will still remain in your FicFairy library.

If you wish to "remove" a work from FicFairy, you can either delete the files themselves or you can use the "hide/unhide" functionality.

Bringing in files you already have

Fics you may have already downloaded from elsewhere should sit in the works folder so they can be picked up for import. If they match the current pattern used by FicFairy to name files, then they can be brought in right away.

Otherwise, the app will flag an issue with an import, and offer to rename the files for you to bring them in line with the rest.
